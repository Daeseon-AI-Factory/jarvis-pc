## 1. 시작 — 사용자 quote

ScreenBridge는 *AI가 시키는 추상적 지시를 사용자 화면에 박는 번역기*. 1인 개발 + 어머님 dogfooding + 글로벌 시장 목표. 박는 동안 사용자가 박은 보안 우려 quote가 있다 — 시간순.

```
[2026-05-29] "근데 이거 진짜 보안문제되겠는데 제미나이가 다 볼거아니냐"
[2026-05-30] "이거는 출시무리인가 로컬 llm 안 쓰는 이상"
[2026-05-30] "계좌 번호가 보이자나 ai한테 비번이나"
[2026-05-30] "은행업무 같은건 못하게 막아야하나"
[2026-05-30] "내 컴터에 각종 은행정보나 오만가지가 있을텐데 나는 왜 아무의심없이 맥북을 쓴걸까"
[2026-05-30] "Claude Computer Use 이런것도 얘네가 어찌 출시한거지 보안 이슈 없었나"
[2026-05-31] "로컬 llm이 비서가 될 수 있을까 성능 병신일거같은데 최신 내용도 모를거아냐"
[2026-05-31] "내가 모르는게 너무 많은데 프로젝트 로그들은 너무 적어보여"
```

이 8 quote가 박힌 *진짜 질문* 3개:

1. **Target user trust** — 어머님/시니어/기업이 이 product에 자기 화면 맡길 수 있나?
2. **Personal risk audit** — 1인 개발자가 출시 후 *책임* 어떻게 지나?
3. **빅테크 비교 정당성** — Operator / Claude CU / Manus는 같은 architecture로 어떻게 ship했나?

이 문서는 8 quote + 3 질문에 1개월 동안 박은 답을 시간순 + architecture 단으로 정리.

## 2. 진짜 문제 — 화면 capture가 무엇을 cloud로 보내나

ScreenBridge v0.1 architecture:

```
[사용자 ⌥+Space]
   ↓
[ScreenCaptureKit fullscreen capture] → PNG ~2MB
   ↓
[Vision OCR (VNRecognizeTextRequest)] → OCRBox[]
   ↓
[AXService (AXUIElement traversal)] → AXElement[]
   ↓
[GeminiDispatcher.analyze(png, instruction)] ←──── HTTPS POST
   ↓                                              generativelanguage.googleapis.com
[AnalysisResult JSON]
   ↓
[HUD red box + 한글 bubble]
```

3번째 줄에 PNG 통째가 Google 서버로 간다. 그 PNG 안에 *우연히* 박혀있을 수 있는 것:

| 시나리오 | 화면에 있는 것 | Gemini가 보는 것 |
| --- | --- | --- |
| Cursor 켜놓고 `.env` 열림 | `ANTHROPIC_API_KEY=sk-ant-xxx` | 전부 |
| Slack 옆에 띄움 | 회사 NDA 채팅 / 친구 카톡 | 전부 |
| 카카오뱅크 frontmost | 잔액 / 거래내역 / 계좌번호 | 전부 |
| 1Password 열림 | password vault | 전부 |
| Mail compose 중 | 작성 중인 메일 본문 | 전부 |
| 의료/법무 문서 | 환자/의뢰인 정보 | 전부 |

사용자가 *의도하지 않은* 데이터가 전부 외부 vendor TLS 너머로 박힌다. Vendor TLS는 transport만 보장, server-side storage/training opt-out은 별도 — *애초에 박지 않는 것*이 유일한 결정적 보호.

이게 사용자 quote 1번 ("제미나이가 다 볼거 아니냐") 의 *literal* 답: **그렇다, 다 본다**.

## 4. 빅테크 사고 사례 (왜 이게 진짜 문제인지)

사용자 quote 6번 ("Claude Computer Use 이런것도 얘네가 어찌 출시한거지") 의 답. 2024 말 ~ 2026 동안 박힌 사고를 정리. 5 incidents.

### 4.1. Claude Computer Use — 출시 *2일 후* HiddenLayer prompt injection PoC

**날짜:** 2024-10-24 (public beta는 2024-10-22)

**사고:** HiddenLayer가 *indirect prompt injection*을 시연. 외부 content (파일/이메일/검색 결과)에 박힌 악성 instruction이 agent를 redirect → 사용자 권한으로 공격자 의도 행동 실행.

**소스:**
- https://hiddenlayer.com/innovation-hub/indirect-prompt-injection-of-claude-computer-use/
- https://www.anthropic.com/news/3-5-models-and-computer-use

**lesson:** Anthropic — Constitutional AI 만든 회사 — 도 day-of-launch에 PoC 박혔다. ScreenBridge는 OCR로 읽은 *모든 화면 텍스트가 적대적 input*이라고 가정해야. **화면 content는 data, never instruction**.

### 4.2. Claude Code — CVE-2025-54794 (path traversal) + CVE-2025-54795 (RCE)

**날짜:** 2025-08

**사고:** Cymulate의 'InversePrompt' 연구:
- CVE-2025-54794 (CVSS 7.7): path 검증 flaw — prefix matching으로 directory restriction 우회
- CVE-2025-54795 (CVSS 8.7): command injection → 임의 코드 실행

**소스:**
- https://nvd.nist.gov/vuln/detail/CVE-2025-54794
- https://cymulate.com/blog/cve-2025-547954-54795-claude-inverseprompt/

**lesson:** "starts with" 식 string prefix는 sandboxing이 아니다. ScreenBridge의 path/permission gate는 *canonical path 비교 + deny-by-default allowlist*로 박혀야 함.

### 4.3. Manus SilentBridge — CVSS 9.8 critical zero-click

**날짜:** 2025

**사고:** Aurascape AuraLabs disclosure. SilentBridge-Doc (CVSS 9.8): *benign* "이 문서 요약해줘" 요청이 → "zero-click agent compromise, arbitrary code execution, root-level control inside agent sandbox, high-sensitivity connector access" → Gmail 데이터 절도 + API key/secret 절도 + agent runtime root shell.

**Manus waitlist 2026 기준 500,000+ 사용자** — blast radius 거대.

**소스:** https://aurascape.ai/resources/auralabs-research/silentbridge-zero-click-agent-takeover-meta-manus/

**lesson:** Sandbox는 깨진다. Connector (Gmail 등) 가 blast radius를 "agent did a weird thing"에서 "공격자가 내 inbox + API key 가져감"으로 증폭. **ScreenBridge v0.1은 mail/messages에 인증된 read access 통합 절대 금지** — "guide user to click" lane에만 머물러야.

### 4.4. Manus credit-drain — operational 사고

**사고:** runaway-loop credit drain. "Agent Mode가 monthly allocation을 *분 단위로* 다 태움". 3,200 task 분석: credit waste 72.4%가 3 패턴 (kitchen-sink prompts 31.2% / retry loops 23.8% / wrong model routing 17.4%). Trustpilot 불만 박힘. No refund.

**소스:**
- https://www.eesel.ai/blog/manus-ai-pricing
- https://dev.to/rafsilva85/i-analyzed-10000-manus-ai-tasks-and-found-73-of-credit-waste-comes-from-just-3-patterns-iip

**lesson:** Token/credit metering + hard cap on agent loop iteration은 *product safety feature*. ScreenBridge는 (a) action 당 LLM call hard-cap, (b) real-time cost meter, (c) N step 동일 state면 abort 박아야.

### 4.5. Microsoft Recall — plaintext SQLite + 6개월 출시 지연

**날짜:** 2024-05-30 (Beaumont disclosure), 출시 6→10→12월 지연

**사고:** Kevin Beaumont가 시연: "각 snapshot의 OCR data가 plaintext SQLite DB에 저장. 사용자가 로그인된 상태에서 readable, 암호화 안 됨." 추후 다른 연구자가 fix 우회 시연 ("171 lines of code"). 소셜 미디어 "Hell no" / "Why would anybody want this feature?" 바이럴.

**소스:**
- https://doublepulsar.com/microsoft-recall-on-copilot-pc-testing-the-security-and-privacy-implications-ddb296093b6c
- https://blogs.windows.com/windowsexperience/2024/06/07/update-on-the-recall-preview-feature-for-copilot-pcs/

**결과:** Microsoft가 (a) 6월 → 10월 → 12월 launch 지연 (b) opt-in default로 재작성 (c) BitLocker at-rest 암호화 (d) Windows Hello 인증 필수. Copilot+ PC flagship launch narrative 망함.

**lesson:** OCR'd screen content 저장한다면 *day one부터* encrypt at rest, biometric gate, opt-in, 공개 threat model. "we'll fix it later" 패턴은 6개월 + flagship narrative cost. **ScreenBridge: 스크린샷 default 영구 저장 X. 저장 시 Keychain-derived key로 encrypt.**

### 4.6. OpenAI Operator / Atlas — "may never be fully solved" 공개 자백

**날짜:** 2025-12-22

**사고:** OpenAI Head of Preparedness + 공식 블로그: prompt injection은 "open challenge for agent security" / "**unlikely to ever be fully solved**". 데모: 공격자 이메일이 사용자 inbox에 들어가서 → agent가 out-of-office reply 대신 *resignation message* 전송.

**소스:**
- https://openai.com/index/hardening-atlas-against-prompt-injection/
- https://techcrunch.com/2025/12/22/openai-says-ai-browsers-may-always-be-vulnerable-to-prompt-injection-attacks/

**lesson:** OpenAI가 "fully solved 안 됨" 박았다면 ScreenBridge도 promise 못 함. **유일한 신뢰 가능 safety story = human-in-the-loop confirmation before destructive action** — 이미 ScreenBridge product thesis. *limitation*이 아니라 *feature*로 marketing.

### 4.7. Apple Intelligence + PCC — *유일하게 사고 X* (대조)

**Apple PCC 패턴:** stateless computation + enforceable guarantees + no privileged access + non-targetability + verifiable transparency. Custom Apple Silicon + Secure Enclave + E2E encrypted device → cloud + 요청 직후 데이터 삭제. **사전 공개 threat model + invited red team + bug bounty**.

**소스:** https://security.apple.com/blog/private-cloud-compute/

**lesson:** *공개 threat model + 사전 review 초대*가 Microsoft Recall "ship and patch" 의 반대. PR cost (Beaumont-style takedown) 거대 vs PR benefit (Matthew Green-style endorsement) 거대. **ScreenBridge는 public beta 전에 1-page threat model (데이터 flow / secrets / what leaves device) 박아야**.

## 5. 빅테크가 *왜 ship 가능*했나 — 4 pattern

사용자 quote 6번에 대한 더 깊은 답. 빅테크 5개 product의 launch model을 비교하면 *공통 4 pattern*이 보임.

### Pattern 1 — Gate by user population, not by capability

| Product | Gate |
| --- | --- |
| Claude Computer Use | API-only + 개발자 beta flag |
| OpenAI Operator | $200/월 ChatGPT Pro + US-only |
| Manus | Waitlist (500k+) + credit metering |
| Microsoft Recall | Copilot+ PC 하드웨어 + opt-in |
| Apple Intelligence | iPhone 15 Pro+ / M-series 한정 |

**모두 capability를 좁힌 게 아니라 *WHO*를 좁혔다**. 좁은 audience = manageable blast radius + concentrated telemetry + filterable abuse.

**ScreenBridge implication:** open download 전에 *TestFlight 작은 beta cohort*로 ship. 사용자 식별 가능한 작은 집단에서 검증.

### Pattern 2 — Pre-declare the limits in writing

| Product | Label |
| --- | --- |
| OpenAI | "unlikely to ever be fully solved" |
| Anthropic | "public beta" / "developer preview" |
| Manus | "research preview" |
| Microsoft | "preview for Insiders" |
| Apple | "published threat model" |

모든 shipper가 *사용자의 reasonable expectation of reliability*를 낮추는 라벨 박음 — 단일 가장 강한 legal + PR shield.

**ScreenBridge implication:** launch label = "assistive preview, you confirm every click" — *autonomous agent* 아님.

### Pattern 3 — Human-in-the-loop is the only defense everyone agrees on

| Product | HITL 정도 |
| --- | --- |
| Google Mariner | default HITL |
| OpenAI Atlas | hardening + admission "unsolvable" |
| Claude CU | day-of-launch PoC, dev-only gate |
| Manus | autonomous → SilentBridge sandbox 깨짐 |

산업 합의 (revealed preference): **모델은 사용자 화면에서 unsupervised 행동 신뢰 불가**.

**ScreenBridge implication:** "guide-and-confirm, never auto-click"이 *이미 산업이 검증한 safe mode* — feature로 marketing.

### Pattern 4 — Persistence + plaintext = career-ending press cycle

- Microsoft Recall = 스크린샷 캡처가 아니라 *plaintext SQLite*로 망함
- Manus SilentBridge = persisted Gmail token + 공격자 도달 가능 → catastrophic
- 라디오액티브 조합 = (a) 화면 content 저장 + (b) 공격자/타 사용자 도달 가능

**ScreenBridge implication:** default로 스크린샷 disk 저장 X. 저장 시 Keychain-derived key encrypt + biometric read gate.

### 4 pattern → ScreenBridge가 *같은 길 못 감*

빅테크 4 pattern은 **legal/insurance/scale infrastructure가 있어야 박힘**:
- API-only gate = Anthropic legal team이 ToS shield
- $200/월 paywall = OpenAI가 user 식별 + arbitrage 가능
- Sandbox VM = Operator는 cloud VM에서 격리 실행
- Connector audit = Manus enterprise compliance review

ScreenBridge = **1인 개발 + 어머님 target + Mac native**:
- Legal team 없음 → ToS shield 약함
- $200/월 paywall = senior 못 씀 (memory: target-user-senior-non-tech)
- Sandbox VM = native macOS 앱 = 사용자 머신에 직접 박힘
- Connector enterprise audit = 1인 review 불가

→ **ScreenBridge는 빅테크 4 pattern 중 *어느 하나도 못 쓴다***. 다른 길 박아야. 그게 §6 5-layer 보안 architecture + §8 local-first.

## 6. ScreenBridge 5-layer 보안 architecture

박힌 5 layer + 각각의 박힘/빠짐 상태.

### Layer 1 — Text-level secret detection (regex) ✓ 박힘 (commit `2ffc163`)

**file:** `Sources/ScreenBridge/SecretMasker.swift`

10 pattern, *specific → generic* 순서 (sk-ant- 가 sk- 앞에):

```swift
// SecretMasker.swift
static let patterns: [Pattern] = {
    let raw: [(String, String, String)] = [
        ("anthropic-key",      #"sk-ant-[a-zA-Z0-9_-]{20,}"#,    "[REDACTED:anthropic-key]"),
        ("openai-project-key", #"sk-proj-[a-zA-Z0-9_-]{40,}"#,   "[REDACTED:openai-key]"),
        ("openai-key",         #"sk-[a-zA-Z0-9]{20,}"#,          "[REDACTED:openai-key]"),
        ("google-ai-key",      #"AIza[a-zA-Z0-9_-]{35}"#,        "[REDACTED:google-key]"),
        ("aws-access-key",     #"AKIA[0-9A-Z]{16}"#,             "[REDACTED:aws-access-key]"),
        ("github-pat-new",     #"github_pat_[a-zA-Z0-9_]{82}"#,  "[REDACTED:github-token]"),
        ("korean-rrn",         #"\b\d{6}[-\s]\d{7}\b"#,          "[REDACTED:rrn]"),
        ("credit-card",        #"\b(?:\d{4}[-\s]?){3}\d{4}\b"#,  "[REDACTED:card]"),
    ]
    return raw.compactMap { name, pattern, replacement in
        guard let r = try? NSRegularExpression(pattern: pattern) else { return nil }
        return Pattern(name: name, regex: r, replacement: replacement)
    }
}()
```

`AnalyzeCoordinator.run()` 경계에서 instruction + audit 양쪽 mask. *Email은 mask 제외* — 사용자 instruction "내 이메일 어디 입력?" 보존 필요.

**ROI:** ~1ms regex, false positive (사용자 좌절) 영향 100배 가벼움 vs false negative (secret 유출).

### Layer 2 — App-level routing (frontmost bundleID) ✗ 다음 박을 거

**file (예정):** `Sources/ScreenBridge/SensitivityRouter.swift`

deny-list (v0.2 박을 거):

```swift
static let defaultExcluded: Set<String> = [
    // 비밀번호
    "com.1password.1password7",
    "com.1password.1password8",
    "com.bitwarden.desktop",
    "org.keepassxc.keepassxc",
    "com.apple.keychainaccess",
    // 한국 은행
    "com.kakaobank.kakaobank",
    "com.kbstar.kbbank",
    "com.shinhanbank",
    "com.kebhana.HanaOneQ",
    "com.viva.toss",
    "com.wooribank",
    // 신용카드
    "com.shinhancard",
    "com.bccard",
    "com.samsungcard",
]

@MainActor
static func currentFrontmostExcluded() -> (bool: Bool, name: String?) {
    guard let app = NSWorkspace.shared.frontmostApplication,
          let bid = app.bundleIdentifier else { return (false, nil) }
    return (isExcluded(bundleID: bid), app.localizedName)
}
```

`AnalyzeCoordinator.run()` 진입 직후 호출. excluded면 early return + HUD "이 화면은 인터넷에 안 보내요". v0.2 SensitivityRouter는 *fail-closed* (불확실 시 차단) — 누락 1건 = 신뢰 영원 lose, 과차단 = 회복 가능.

### Layer 2.5 — Content-level masking (OCR + AX) ✗ v0.3

Layer 1/2 둘 다 통과한 case: 일반 Chrome에서 GitHub settings 페이지 열고 "내 PAT 어디?" — OCR이 `ghp_xxx` 박스 뽑아 Gemini에 보냄. Layer 2.5는 OCR 결과 각 box에 `SecretMasker.mask()` 적용 + *image pixel도 검은 사각형 fill*.

            return OCRBox(text: SecretMasker.mask(box.text), ...)

        return box

    // CGContext draw + black fillRect on redactedRects → re-encode PNG
    ...
}

### Hybrid Architecture — Local image + Cloud knowledge (opt-in)

Layer 4만 쓰면 정확도/지식 천장 (~70-80%, 최신 앱 UI 모름). 두 단계 분리:

```swift
// HybridAnalyzeCoordinator.swift (model code)
actor HybridAnalyzeCoordinator {
    func run(maskedImage: Data, imageSize: CGSize, instruction: String) async throws -> HybridAnalysisOutput {
        // Step (a) — local만. 사용자 데이터 전부 device 안.
        let local = try await localDispatcher.analyze(...)

        // Step (b) — optional cloud. *공개 식별자만* 보냄.
        guard cloudKnowledgeEnabled,
              let appLabel = local.detectedAppLabel,   // "Visual Studio Code"
              let intent = local.normalizedIntent      // "open_settings"
        else { return ... localOnly ... }

        let publicQuery = """
        앱: \(appLabel)
        목적: \(intent)
        일반적으로 어떻게 진행되는지 한 줄로 설명.
        (사용자 식별자/스크린샷 X — 공개 매뉴얼만 참고.)
        """
        let enrichment = try await cloud.knowledgeQuery(text: publicQuery)
        return HybridAnalysisOutput(
            result: AnalysisResult.merge(local: local, cloudHint: enrichment),
            localCalls: 1, cloudCalls: 1,
            cloudPayloadDigest: "앱이름=\(appLabel), 의도=\(intent)"  // HUD 표시
        )
    }
}
```

**Privacy receipt UX:** HUD에 "local 1회, cloud 0회" 매 분석마다 정직히 표시. 사용자 trust mental model 깨지면 신뢰 무너짐.

## 11. 다른 사람을 위한 lesson

비슷한 vision-LLM agent 박을 사람을 위한 transferable lesson.

### 1. Local-first가 진짜 답 (그러나 *cloud-first ship + migration* 박아라)

100% local 기다리면 빅테크 흡수 (1-2년 윈도우). Cloud-first ship + local migration path 박는 게 정답.

protocol-based dispatcher 박혀있어야 swap 30분-2일에 박힘:

```swift
protocol LLMDispatcher {
    func analyze(imageData: Data, imageSize: CGSize, instruction: String)
        async throws -> AnalysisResult
}
```

### 2. Cloud-first ship 위험 — Fail-closed routing이 필수

Cloud-first ship 시 *deny-list + audit log* 없이 출시하면:
- 1Password / 카카오뱅크 / Mail compose 화면이 통째 외부 vendor 서버에
- enterprise pilot 불가
- senior 사용자 trust 0

**Fail-closed routing > 100% local** (감사 가능성 측면). 기업 컴플라이언스: "deny-list 매치 시 무조건 on-device, fail-closed"가 더 강함.

### 3. Apple 모델 따라가기 (5 요소)

- On-device 우선 (Foundation Model)
- Private Cloud Compute (Apple 자사)
- Encryption (FileVault / Keychain)
- Granular permission (TCC)
- App Store review (Privacy nutrition labels)

ScreenBridge의 5-layer 보안이 이 5 요소를 미러링.

### 4. 빅테크 사고 학습

| 사고 | Lesson |
| --- | --- |
| Claude CU day-of-launch PoC | 화면 content = data, never instruction |
| Claude Code CVE prefix matching | canonical path 비교 + deny-by-default |
| Manus SilentBridge CVSS 9.8 | Connector = blast radius multiplier |
| Manus credit-drain | Hard cap on loop + cost meter |
| Microsoft Recall plaintext | Day-one encrypt + biometric + opt-in |
| OpenAI Atlas "unsolvable" | HITL = 유일 신뢰 가능 safety story |
| Apple PCC | 공개 threat model + invited red team |

### 5. Conservative bias

**False positive (사용자 좌절) < False negative (secret 유출) × 100**.

의심 시 차단/redact. 매주 자동 fuzz test로 누락 monitor. 누락 1건 = 신뢰 영원 lose.

### 6. Privacy receipt UX

"무엇이 어디 갔나" 매 분석마다 사용자에게 정직히 표시:

```
HUD: local 1회, cloud 0회 (이번 분석)
     보낸 거: 앱이름=Visual Studio Code, 의도=open_settings
```

사용자 trust mental model 깨지면 신뢰 무너짐. Hybrid는 *boundary clarity*가 핵심.

### 7. Data minimization (GDPR Art.5(1)(c)/(e))

- audit log 7일 rotation
- screenshot disk 영구 저장 X
- instruction raw 보존 X

"필요 이상 가지지 않는다"가 보안의 절반.

### 8. Privacy by design (GDPR Art.25)

5-layer는 v1.0 ship *전*에 모두 박혀야 함. v1.0 후 add-on 박으면 already-shipped data 처리 분쟁 (마이그레이션 비용 폭발).

ScreenBridge에서 v0.0에 보안 미인식 → v0.2 시점에 박기 시작 = *늦은 편*. 다른 사람은 v0.0에 5-layer skeleton 박고 시작 권장.
